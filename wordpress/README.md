# Instagram у слайдері Pinko Studio

**Список слайдів керується опублікованими записами WordPress із категорії `portfolio_slider` та їхнім ACF-полем `portfolio_link`.** Поле `portfolio_photo` не використовується. Збережені копії дописів не додають слайдів самостійно: видалений із WordPress запис зникає зі слайдера.

## Поточна робота без налаштованого API

Для шести раніше підключених URL відновлені збережені фото, відео, підписи й дати, щоб картки та власне модальне вікно працювали як раніше. Медіа лежать у `public/media/instagram/`, а відповідні дані збережені прямо в `PortfolioSlider.jsx`. Ці копії не оновлюються автоматично з Instagram. Один довгий підпис збережений стислим переказом; це позначено в його даних. Коментарі не показуються.

Слайдер складається з двох JavaScript-компонентів: `PortfolioSlider.jsx` отримує записи WordPress, містить збережені дані й запити Instagram API; `InstagramEmbed.jsx` перевіряє URL та показує картку, відеопрев’ю і модальне вікно. Всі їхні стилі зібрані в `portfolioSlider.scss`. Окремих JSON-файлів, Instagram-сервісу, файлів-помічників і тестів немає. `service.js` залишається спільним місцем для запитів WordPress.

Доступ до робочого серверного Instagram API зараз не налаштований. Нижче описаний додатковий режим, який можна підключити пізніше з дозволу власниці акаунта. Для нового URL без збереженої копії слайдер пробує цей API; без налаштованого доступу або після невдалого запиту використовується **стандартний Instagram Embed**. Допис має бути доступним для вбудовування на стороні Instagram.

Вміст iframe контролює Instagram: сайт не читає з нього фото й опис для власної верстки. Серверний плагін отримує медіа через Instagram API та не парсить HTML Instagram.

## 1. Отримати доступ у Meta

1. Instagram студії має бути **Professional: Business або Creator**. У [Meta for Developers](https://developers.facebook.com/) створіть застосунок і додайте Instagram API з варіантом **Instagram Login**.
2. У розділі налаштування Instagram API додайте обліковий запис студії, увійдіть у нього та надайте дозвіл `instagram_business_basic`. Для цієї інтеграції не потрібні дозволи на публікацію чи повідомлення. Facebook Page для Instagram Login не обов’язкова. У режимі розробки обліковий запис повинен мати дозволену роль/бути тестером застосунку та прийняти запрошення, якщо це запитує Meta.
3. Згенеруйте access token для цього Instagram-акаунта. Збережіть **IG User ID** того самого акаунта з відповіді авторизації або запиту `/me` відповідно до документації Meta. Це не ім’я профілю і не ID Facebook Page.
4. Для робочого сайту використовуйте довгостроковий токен. Короткостроковий токен потрібно обміняти на довгостроковий на сервері за процедурою Meta. Перед закінченням строку дії оновлюйте токен через `refresh_access_token`; зберігайте повернений токен і строк дії. Після відкликання доступу або прострочення потрібно авторизуватися повторно. Плагін **не виконує OAuth і не оновлює токен автоматично**. Встановіть собі нагадування про оновлення та перевіряйте фактичний `expires_in`.

Налаштування токенів та доступ для чужих акаунтів залежать від статусу застосунку: Meta може вимагати App Review/Advanced Access. Цей плагін читає тільки медіа акаунта, який авторизував застосунок. Довільні чужі публічні дописи за URL він отримати не може.

Офіційні джерела: [Instagram API з Instagram Login](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/), [Business Login і токени](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/business-login), [офіційна колекція Instagram API від Meta](https://www.postman.com/meta/instagram/overview). Назви пунктів кабінету Meta можуть змінюватися.

## 2. Установити плагін у WordPress

Скопіюйте папку `pinkostudio-instagram` у `wp-content/plugins/` на сервері WordPress і активуйте **Pinko Studio Instagram** в адмінці. Або запакуйте цю папку в ZIP та завантажте через «Плагіни → Додати новий → Завантажити плагін».

У `wp-config.php` на сервері WordPress **перед** рядком `/* That's all, stop editing! */` додайте:

```php
define( 'PINKO_INSTAGRAM_ACCESS_TOKEN', 'ВСТАВТЕ_ТОКЕН_НА_СЕРВЕРІ' );
define( 'PINKO_INSTAGRAM_USER_ID', 'ВСТАВТЕ_ЧИСЛОВИЙ_IG_USER_ID' );
// Необов’язково: типове значення плагіна — v25.0.
define( 'PINKO_INSTAGRAM_API_VERSION', 'v25.0' );
```

Токен не можна додавати в React, `REACT_APP_*`, ACF, публічний REST API, Git або скриншоти. Плагіну достатньо цих двох секретних серверних налаштувань; App Secret він не використовує. Версію Graph API можна змінити константою після перевірки [журналу версій Meta](https://developers.facebook.com/docs/graph-api/changelog/versions) та тестування запиту. Вибрана v25.0 є випущеною версією; це не автоматичне перемикання на найновішу версію.

## 3. Перевірити відповідь

Відкрийте у браузері:

```text
https://api.pinkostudio.artemsokur.com/wp-json/pinkostudio/v1/instagram?url=https%3A%2F%2Fwww.instagram.com%2Fp%2FDJ3oIc4NRMg%2F
```

Успіх — JSON з `img`, `caption`, `hashtags`, `username`, `timestamp`, `mediaType` та масивом `media`. Поле `img` завжди містить фото або обкладинку відео для картки; `media[].type` — `image` або `video`. Опис та хештеги можуть бути порожніми, якщо Instagram їх не повернув. Перевірте також другий URL. Фронтенд використовує цей самий REST-домен, що й поточні записи WordPress; якщо його адреса зміниться, змініть наявне налаштування API сайту.

Основні коди помилок:

- `pinko_instagram_not_configured` (503): немає коректних серверних констант.
- `pinko_instagram_api_unavailable` (502): мережа, токен, дозволи або помилка Meta. Перевірте обліковий запис та токен у кабінеті Meta. Секретні деталі відповіді Meta публічний маршрут не показує.
- `pinko_instagram_post_not_found` (404): допис не повернувся в медіа підключеного акаунта або не має доступного зображення. Пошук обмежено 10 сторінками по 100 записів; якщо допис старіший або недоступний через API, потрібне окреме розширення пошуку/збереження IG Media ID.
- `pinko_instagram_url_not_allowed` (403): посилання відсутнє в серверному списку дозволених.

Успішні дані кешуються на годину, помилки API — на хвилину. Зміна токена, ID, версії або списку дозволених створює новий кеш. Посилання на медіа Meta мають обмежений строк дії, тому не копіюйте їх як постійні адреси картинок. Цей серверний кеш працює окремо від збережених копій шести дописів у React.

## Керування посиланнями з WordPress

У групі ACF «Портфоліо Слайдер» використовуйте поле `portfolio_link` типу URL та увімкніть показ групи в REST API. Додайте Instagram-посилання до запису, виберіть категорію «Портфоліо Слайдер» (`portfolio_slider`) й опублікуйте запис. Чернетки не потрапляють у публічний слайдер. Для зміни списку редагуйте, додавайте або прибирайте ці записи в WordPress. Старе поле `portfolio_instagram_url` підтримується для сумісності, але створювати його додатково не потрібно. Поле фото можна видалити: обкладинка береться з медіаданих за Instagram-посиланням.

У коді плагіна публічний API дозволяє лише два URL. Нові URL також потрібно дозволити **на сервері** фільтром `pinkostudio_instagram_allowed_urls` у власному плагіні або темі:

```php
add_filter( 'pinkostudio_instagram_allowed_urls', function ( $urls ) {
    $urls[] = 'https://www.instagram.com/p/НОВИЙ_SHORTCODE/';
    return $urls;
} );
```

На наступному етапі цей фільтр можна заповнювати URL із потрібних опублікованих записів ACF. Саме наявність URL у фронтенді не дає серверу права читати всі медіа акаунта. Механіка Swiper від цього не змінюється.
